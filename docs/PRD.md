## 1. 개요

**어디 갈래**는 관광지·축제를 둘러보고 비교하고, 취향에 맞춘 AI 여행 코스를 받아 여행으로 저장하고, 구글 캘린더에 올려 주는 데스크톱 웹 서비스입니다.

```
검색·탐색(표 + 지도) ──┬─ 비교 담기 ─┐
상세 → 함께 가기 좋은 곳 ┘            ├─▶ AI 코스 추천 ─▶ 여행에 저장(일정안) ─▶ 확정 ─▶ 구글 캘린더
찜 ──────────────────────────────────┘        ▲                                         │
                                              └────── 행동 데이터·방문 확인 ◀────────────┘
```

- 데이터 원천은 한국관광공사 **TourAPI**(관광지·축제·음식점·숙박)입니다.
- 서버는 사용자 선호 프로필로 후보 장소를 고르고(**무엇을 좋아할지**), AI는 일차별 순서와 시간표를 짭니다(**어떻게 엮을지**).
- 여행 하나에 일정안(예: 기본 코스, 비 오는 날 코스)을 여러 개 두고 하나를 확정합니다.
- 여행을 다닐수록 조회·찜·일정 저장·방문 만족도가 쌓여 추천이 개인화됩니다.

## 2. 문제와 목표

| 사용자 문제 | 서비스가 주는 해결책 |
|---|---|
| 지금 어디서 어떤 축제를 하는지 한눈에 보기 어렵다 | 진행중·예정 축제를 지도와 표로, 지역·카테고리 필터와 D-day와 함께 보여준다 |
| 가고 싶은 곳 여러 개를 놓고 고르기 어렵다 | 비교 담기로 모아 지도에서 함께 보고, 기간 겹침·휴무일을 요약해 준다 |
| 여러 장소를 동선·운영 시간·이동 수단까지 고려해 엮는 데 시간이 오래 걸린다 | 조건만 입력하면 일차별 코스, 이동 수단, 식사 시간까지 자동으로 짜 준다 |
| 날씨나 상황에 따라 계획을 바꾸고 싶다 | 한 여행에 일정안을 여러 개 두고 상황에 맞게 확정을 바꾼다 |
| 짠 일정을 캘린더에 일일이 옮겨 적어야 한다 | 확정 일정안을 원하는 구글 캘린더에 한 번에 올리고, 수정·교체·삭제도 동기화한다 |
| 추천이 내 취향과 맞지 않는다 | 온보딩 취향 + 행동 데이터 + 동행 유형별 프로필로 추천을 개인화한다 |

**제품 목표**

1. 사용자가 조건 입력부터 저장 가능한 여행 코스를 받기까지 30초 안에 끝낸다 (AI 응답 대기 상한 30초).
2. AI가 실패해도 사용자는 항상 쓸 수 있는 코스를 받는다 (기본 코스 대체).
3. 확정 일정안과 사용자의 구글 캘린더가 어긋나지 않는다 (서비스 → 캘린더 단방향 동기화).

## 3. 대상 사용자와 핵심 시나리오

명세의 동행 유형(혼자, 연인, 친구, 아이 동반, 부모님)이 주요 사용자군입니다.

| 시나리오 | 흐름 | 관련 기능 |
|---|---|---|
| A. 주말 축제 찾기 | 검색 시작 → 탐색(축제 탭, "이번 주말") → 상세 → 찜 | 002-01~05, 002-07 |
| B. 후보를 비교해 코스 받기 | 탐색·찜에서 비교 담기 → "이 장소들로 코스 추천" → 추천 요청(장소 자동 채움) → 결과 | 002-08, 003-01~02 |
| C. 마음에 든 축제 주변으로 코스 짜기 | 상세 → 함께 가기 좋은 곳 체크 → "이 장소로 코스 추천받기" | 002-04, 002-09, 003-01 |
| D. AI로 1박 2일 코스 받아 저장 | 추천 요청 5단계 → 결과(타임라인 + 지도) → 식사 장소 선택 → "여행에 저장"(새 여행 또는 기존 여행의 일정안) | 003-01~06, 003-10, 004-07 |
| E. 비 오는 날 대비 | 여행 상세 → "+ 일정안 추가"(AI, "실내 위주로 짜기" 켬) → 여행 상세에서 타임라인 확인 → 확정 바꾸기 | 004-04, 004-08 |
| F. 캘린더에 올리기 | 마이페이지 캘린더 연동 → 여행 상세 "캘린더에 올리기" → 캘린더 선택·항목 선택 → 올리기 | 005-01~04 |
| G. 다녀온 뒤 | 내 여행 "다녀오셨나요?" 배너 → 장소별 방문 여부·만족도 | 003-09 |

## 4. 범위

### 4.1 이 저장소(FE)의 범위

- 아래 [6. 화면 구조](#6-화면-구조)의 모든 화면과 상호작용
- 2D 지도 렌더링 (탐색 마커, 코스 마커·경로 선, 도보 반경, 지도 범위 이동, "이 지역에서 다시 찾기")
- 클라이언트 측 처리: 입력 검증(서버와 같은 규칙), 낙관적 업데이트, 무한 스크롤, 최근 검색어·비교 목록(브라우저 저장), 축제 진행상태 라벨 계산(KST 기준)
- 브라우저 위치 권한 요청과 현재 위치 처리 (좌표는 저장하지 않음)
- 로그인 필요 모달과 로그인 후 동작 이어서 실행
- 비동기 작업(캘린더 업로드 등)의 진행 상태 조회·표시
- 서버 에러 코드별 사용자 안내 ([8.2 에러 코드](#82-에러-코드와-fe-처리))

### 4.2 이 저장소의 범위 밖 (백엔드 담당)

명세에서 `없음(서버)`로 표시된 기능입니다. FE는 결과만 사용합니다.

- TourAPI 동기화 배치 (006-01), 상세 정보 캐시 (006-02), 인기 점수 집계 배치 (006-03)
- 행동 데이터 수집·선호 프로필 계산 (003-08)
- AI 호출, 후보 추출, 응답 검증, 경로 API 호출과 캐시, 주변 장소(함께 가기 좋은 곳) 조회
- 캘린더 동기화 작업 실행 (005-04)

### 4.3 제품 범위 밖 (명세상 하지 않는 것)

- 3D 지도, 코스 미리보기 재생
- 웹 푸시 알림 (방문 확인은 배너 + 이메일)
- 구글 캘린더 → 서비스 방향 동기화 (캘린더에서 직접 고친 내용은 반영하지 않음)
- 온보딩에서 동행 유형·이동 수단 입력 (동행은 추천 요청 시 입력, 이동 수단은 서비스가 추천)
- 구글 외 소셜 로그인
- 현재 위치 좌표의 저장 (추천 요청에만 쓰고 버림)

## 5. 기능 요구사항

우선순위: **P1** = 필수(MVP), **P2** = 중요, **P3** = 있으면 좋음. 진행 상태는 2026-10-23 기준 모두 "시작 전"입니다.

### 5.0 접근 권한

| 구분 | 대상 |
|---|---|
| **공개** (비로그인 가능) | 검색 시작(홈), 탐색(목록·지도·필터·정렬·검색), 상세 조회(함께 가기 좋은 곳 포함), 비교 담기, 로그인·회원가입·비밀번호 찾기 |
| **로그인 필요** | 찜하기·찜 목록, 비교 장소로 코스 추천, AI 추천, 내 여행·일정 편집·캘린더, 마이페이지, 온보딩 |

**비로그인 사용자가 로그인 필요 기능에 접근할 때** (디자인 14-1, 14-2)

1. **화면 안의 버튼**: 로그인 필요 모달 하나를 상황별 문구로 띄운다. 버튼은 [로그인] [Google로 계속하기] [회원가입] [계속 둘러보기·나중에·계속 비교하기]. 버튼 자체는 숨기지 않는다.
2. **로그인 필요 화면으로 이동** (상단 메뉴, URL 직접 입력, 공유 링크): 원래 주소를 복귀 주소로 넘기며 로그인 페이지로 이동한다.
3. **로그인 후 이어서 실행**: 원래 화면으로 돌아와 누른 동작을 이어서 실행한다. 온보딩을 마치지 않은 계정은 온보딩을 먼저 마친다.

   | 누른 것 | 로그인 후 |
   |---|---|
   | ♥ 찜 | 보던 상세로 돌아와 찜 저장 |
   | 상단 메뉴 AI 추천 | 추천 요청 1단계로 이동 |
   | 비교 트레이 "코스 추천" | 추천 요청에 비교 장소를 꼭 포함할 장소로 채움 |
   | + 일정에 추가 · 내 여행 | 어느 여행에 담을지 묻는 모달 표시 |

4. **복귀 주소 검증**: 서비스 내부 경로만 허용한다. 외부 주소가 오면 검색 시작 화면으로 보낸다(오픈 리다이렉트 방지).
5. **세션 만료**: 로그인 필요 화면에서 `UNAUTHORIZED`(리프레시 실패)가 오면 2번과 같이 처리한다. 공개 화면에서는 비로그인 상태로 전환만 하고 화면을 유지한다.

| AI 추천 기간 | 당일~최대 3박 4일, 과거 날짜 불가 |
| 꼭 포함할 장소 | 최대 5개 (비교 담기는 제한 없음) |
| 함께 가기 좋은 곳 | 최대 4곳 표시·체크 |
| AI 추천 하루 횟수 | 사용자당 10회(다시 추천 포함), KST 자정 초기화, 기본 코스까지 실패하면 차감 안 함 |
| 목록 페이지 크기 | 20개 (관광지·축제, 찜, 내 여행) |
| 만족도 | 1~5 정수 |

### 8.2 에러 코드와 FE 처리

| HTTP | 코드 | 상황 | FE 처리 |
|---|---|---|---|
| 400 | `INVALID_INPUT` | 형식·길이 위반 | 응답의 필드 정보로 해당 입력란 아래에 안내 |
| 400 | `INVALID_PASSWORD_FORMAT` | 비밀번호 정책 위반·불일치 | 입력란 아래에 안내 |
| 400 | `EMAIL_NOT_VERIFIED` | 이메일 미인증 또는 인증 후 10분 경과 | 인증 단계로 돌려보냄 |
| 400 | `VERIFICATION_CODE_MISMATCH` | 인증코드 불일치 | 남은 입력 횟수 표시 |
| 400 | `VERIFICATION_CODE_EXPIRED` | 만료 또는 5회 초과 | 재발송 유도 |
| 400 | `INVALID_CURSOR` | 잘못된 커서 | 첫 페이지 다시 조회 |
| 400 | `SCHEDULE_LIMIT_EXCEEDED` | 일정안당 장소 30개, 기간, 꼭 포함 5개 초과 | 제한 안내 (사전 검증으로 대부분 막음) |
| 400 | `PLAN_NOT_CONFIRMED` | 확정 일정안이 없는 여행의 캘린더 업로드 | 일정안 확정 안내 |
| 401 | `UNAUTHORIZED` | 로그인 필요·토큰 만료 | 리프레시 시도. 실패 시 로그인 필요 화면이면 복귀 주소와 함께 로그인 페이지로, 공개 화면이면 비로그인 상태로 전환 ([5.0](#50-접근-권한)) |
| 401 | `INVALID_CREDENTIALS` | 이메일·비밀번호 불일치 | 구분 없는 동일 문구 |
| 401 | `CALENDAR_AUTH_EXPIRED` | 캘린더 토큰 만료·권한 철회 | 연동 해제 상태로 표시, 재연동 안내 |
| 403 | `FORBIDDEN` | 다른 사용자의 여행 등 접근 | 접근 불가 안내 |
| 403 | `CALENDAR_NOT_LINKED` | 미연동 상태로 업로드 | 마이페이지 캘린더 연동 안내 후 이동 |
| 403 | `CALENDAR_NOT_WRITABLE` | 선택한 캘린더가 삭제됐거나 쓰기 권한 없음 | 다른 캘린더 선택 안내 |
| 404 | `RESOURCE_NOT_FOUND` | 리소스 없음·삭제 | 안내 후 목록으로 이동 |
| 409 | `EMAIL_ALREADY_EXISTS` | 이미 가입된 이메일 | 로그인·비밀번호 찾기 안내 |
| 409 | `ACCOUNT_LINK_REQUIRED` | 구글 로그인 시 같은 이메일 계정 존재 | 계정 연결 페이지로 이동 |
| 409 | `GOOGLE_ACCOUNT_ALREADY_LINKED` | 구글 계정이 이미 다른 계정에 연결됨 | 연결 불가 안내 |
| 429 | `LOGIN_LOCKED` | 로그인 잠금 | 남은 잠금 시간 표시 |
| 429 | `TOO_MANY_REQUESTS` | IP 요청 한도 초과 | 잠시 후 재시도 안내 |
| 429 | `CODE_RESEND_COOLDOWN` | 재전송 쿨타임 | 남은 초를 버튼에 표시 |
| 429 | `AI_DAILY_LIMIT_EXCEEDED` | 하루 추천 10회 초과 | KST 자정 초기화 안내 |
| 500 | `INTERNAL_SERVER_ERROR` | 예상하지 못한 오류 | 일반 오류 문구 |
| 502 | `EXTERNAL_API_ERROR` | 외부 API 오류 (대체 불가할 때만) | 잠시 후 재시도 안내 |
| 503 | `AI_SERVICE_UNAVAILABLE` | AI·기본 코스 모두 실패 (횟수 미차감) | 재시도 안내, 차감되지 않았음을 표시 |

## 10. 미결 사항

제품 쪽에서 정할 것은 모두 정해졌습니다. 남은 항목은 TRD 또는 백엔드와 정합니다.

1. **2D 지도 SDK**: 카카오맵·네이버 지도 등 국내 지도 중 TRD에서 결정합니다.
2. **카카오 로컬 호출 위치**: FE에서 직접 부를지(앱 키 노출), 서버 프록시를 둘지 TRD에서 결정합니다.
3. **분류 매핑 표**: 여행 스타일·빠른 필터 칩·실내·실외 구분을 TourAPI 새 분류 중분류에 연결하는 표를 TRD에서 확정합니다.
4. **비로그인 조회 집계**: 비로그인 상세 조회를 인기 점수에 넣을지 백엔드와 합의가 필요합니다.
5. **마감일**: Notion 프로젝트 페이지의 마감일이 비어 있습니다. 정해지면 P1부터 그 날짜에 맞춰 나눕니다.
